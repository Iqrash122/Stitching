## Frontend form behavior added in the continuation revision

Editable Studio forms now share one unsaved-change registry rather than registering competing global warning handlers. Meaningful client-side changes are guarded when closing a modal with its close control/backdrop/Escape, during ordinary Inertia navigation, and on browser reload/tab/window exit through `beforeunload`. Intentional form submissions bypass only their own next Inertia visit so a Save action is not mistaken for abandoned work; successful saves clear their dirty baseline on the next render. File selection in the logo form is treated as a deliberate dirty state and resets only after a successful upload.

Server validation is rendered beside known fields with `aria-invalid`/`aria-describedby`, an accessible error summary is provided, and the first invalid control is focused/scrolled into view after errors arrive. Entered values remain in React/Inertia form state on validation/network failure. Custom order, measurement, product, template, credit and logo forms use immediate submission locks in addition to visible processing states so two synchronous submit events cannot create two client requests. The order pricing preview aborts/rejects stale responses so an older response cannot overwrite a newer preview.

**Browser Back/Forward limitation:** ordinary Inertia link/visit navigation is guarded, while hard reload/close uses the browser's native `beforeunload` confirmation. This revision does not claim that every native history Back/Forward traversal is safely cancellable; no brittle `popstate` history rewriting was introduced without a real browser acceptance run. Back/Forward behavior remains an explicit browser-verification item rather than an unverified production claim.
